# Private profile photo assets

Run after migration 012. Keep JWT verification enabled. POST with an authenticated user session and `{photo_path}` prepares only that user's current photo. Normal uploads already generate both variants in the browser. A POST `{backfill:true}` uses the caller's token to invoke the service_role-only pending RPC and processes exactly one current active profile; repeat until `remaining:0`. No credentials or identifiers are accepted to select another account.

Returns only readiness, counts and byte sizes. Reads and writes remain in the private `profile-photos` bucket; originals are preserved. Account deletion cascades to the preview table, and the existing deletion function removes every file in the user's folder. Newly generated thumbnails can be upserted at the deterministic original-path-plus-`.thumb.jpg` key; changing a photo generates a new original path.

Decoder provenance: jSquash WebP 1.5.0 (`npm:@jsquash/webp`, Apache-2.0) with its packaged `codec/dec/webp_dec.wasm`; ImageScript 1.3.0 reduced JPEG decoder from https://deno.land/x/imagescript@1.3.0/utils/wasm/jpeg.wasm (MIT). Both WASM binaries are embedded in index.ts to work with the single-file dashboard deployment. Included license files accompany the binaries. JPEG encoding: jpeg-js 0.4.4 (BSD-3-Clause); PNG decoding: fast-png 6.2.0 (MIT). These runtime packages are pinned in imports, with matching dev dependencies for codec tests; ImageScript 1.3.1 is used only to generate test pictures locally, not imported by the Edge Function.

Limits: source size 8 MiB, bounded PNG/WebP decoded pixels, reduced JPEG decoding, proportional thumbnails max 480 px and previews max 120 px. Preview length is validated in SQL. The server checks the authenticated user and current photo before processing; service_role-only storage commit additionally checks current active ownership and the actual private thumbnail object. A read failure leaves the original available and permits retry.
