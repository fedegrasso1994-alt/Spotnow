# Daily Discovery hosted staging rehearsal

Manual, disposable-fixture harness. Never run on Production. Not imported into the application, CI or scheduler. Requires migration 037 and an operator-verified Soma Staging dashboard (`zjinjtkekmaqtxsuyvho`). No service/admin API keys. Existing normal Auth confirmation remains ON.

All commands run from repo root with the existing ignored staging frontend env loaded (never root `.env.local`). `make-fixtures.mjs` generates 12 throwaway passwords and a private SQL seed under ignored `.local/daily-discovery/`, mode0600. Do not print or commit those files. Inspect the guard and execute seed ONLY in staging; addresses are `example.invalid`, synthetic marker and exclusive `fea37000-*` namespace. `prepare.mjs` uses real normal password sign-in, AGE/consent, unchanged PHOTO canonical upload, profile and membership APIs. Fixture JPEG is the existing strict-prevalidated canary generator, no real photo.

`sql/allocation-a.sql` snapshots catalog flags, hides nonfixture catalog entries only inside an uncommitted transaction, calls normal RPC as the fixture authenticated principal, restores flags BEFORE COMMIT, and holds the existing lock for an intentional12s. No external session sees baseline catalog flags changed. Start `allocation-b.sql` during that hold in a separate dashboard session; verify different backend PIDs and waiting before the same ready allocation. Temporary tables/permissions are session-local only, not persistent public resources.

Run `first-window.mjs`, then `make-race.mjs 1`: execute generated quota A and B SQL in independent sessions, within A's intentional10s hold. These use a temporary exception catcher so the denied attempt is recorded. Never retry denied requests automatically. `cross-surface.mjs` exercises normal ORA→TRIBE Match/chat. `smallpool.sql` and `recurrence.sql` end in ROLLBACK: only synthetic membership/context modifications, nothing permanent. They prove undersized pool and71h refusal without inventing real exposure history.

`allocation2-a.sql` + allocation B repeat concurrent generation at daily exposure boundary. `second-window.mjs`, then `make-race.mjs 2` test fourth/day Spot race. Save both results/PIDs as evidence. `live-expiry.sql` is an8s fixture window with9s sleep, entirely ROLLBACK; requires window2 present, checks authorized profile gone even within one long SQL batch. This exposed and fixed the original statement_timestamp inconsistency. `integrity.sql` is read-only. Run it before the explicit leave test, because membership deletion legitimately removes exposure rows while keeping already-spent allocation counters (no refill).

`post-fix.mjs` verifies free pending replay at quota cap, fifth NEW denied, Match and chat preserved after leave. `delete.mjs` uses only normal delete-account for all12 fixtures and verifies Auth no longer usable. Only after success run guarded `restore.sql`: removes the two synthetic windows/catalog/Place, restores original discovery OFF / policy disabled+paused+NULL retention. No cleanup/scheduler activation. `postcheck.sql` and `technical-receipts.sql` verify baseline and exact residuals. PHOTO technical tombstones are deliberately preserved by existing seven-day lifecycle; do not purge them ad hoc. Remove local private credentials/seed afterwards.

The scripts are an operator rehearsal, not a general fixture creator/cleanup endpoint. Do not rerun with existing namespace/objects. No Google OAuth/MFA configuration is touched. No final daily clock policy, frontend, retention job or provider is introduced.
