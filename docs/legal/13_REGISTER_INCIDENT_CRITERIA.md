# SOMA Legal Control Register — Incident-readiness criteria supplement

This file defines the canonical criterion for INC controls.

| ID | Canonical requirement | Priority |
|---|---|---:|
| INC-01 | SOMA must maintain a minimal incident register capable of recording detection, scope, owner, assessment, action and closure. | P0 |
| INC-02 | The incident process must support recording the point at which a personal-data breach becomes known with sufficient certainty for GDPR timing purposes. | P0 |
| INC-03 | The process must support a documented supervisory-notification decision within the applicable GDPR timing framework once awareness is established. | P0 |
| INC-04 | A current template/checklist for supervisory-authority notification must be available for use when required. | P1 |
| INC-05 | A current template/checklist for affected-user communication must be available for use when required. | P1 |
| INC-06 | A documented procedure must exist for revoking or rotating affected credentials and sessions after a compromise. | P0 |
| INC-07 | Critical providers must have a documented incident-escalation/contact path feeding SOMA's incident process. | P0 |
| INC-08 | Incident evidence must be preserved in a minimized, access-controlled and time-limited manner. | P1 |
| INC-09 | Before pilot, SOMA must complete and record at least one incident-response tabletop or equivalent rehearsal covering detection, containment, assessment and escalation. | P0 |
