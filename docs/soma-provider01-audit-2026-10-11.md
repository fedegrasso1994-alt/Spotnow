## B. Data flow per provider

1. Browser → DNS/TLS/Vercel/CDN → HTML/JS/CSS/PWA. `/ ?venue=...` (senza spazio nell'URL reale) può comparire nei request log Vercel; non inviare contenuti nelle query. Frontend → Google Fonts già alla home, prima di qualsiasi consenso dating.
2. Browser → Supabase Auth → Google OAuth → Supabase callback → browser. Supabase conserva identity/session; OAuth può restituire nome/avatar oltre all'email; non vengono usati automaticamente come foto obbligatoria Soma. Scope aggiuntivi non richiesti nel codice; scope/provider configuration effettiva Google Cloud MANUAL.
3. Alternativa email: browser → Auth → SMTP default → mailbox del destinatario → callback app. Token deve restare fuori log/export/ticket. Un provider di inbox del destinatario non è automaticamente un processor contrattato da Soma.
4. Browser autenticato → Supabase API/RPC → DB; risposta solo autorizzata → browser. Profilo, Ora, Tribe, Spot, match, chat e report risiedono qui. Chat usa polling5s nel sorgente, non un provider realtime esterno; eventuali Realtime enablement provider MANUAL.
5. Foto ≤8MiB → Supabase photo-assets → normalizer JPEG/PNG/WebP nello stesso progetto → canonicale+detail+thumb su Storage privato → URL signed30s → browser/cache. Buffer originali transitori, nessun originale persistito dalla pipeline nuova; nessun servizio esterno immagini. Raw richiesta attraversa comunque gateway/runtime/log provider: non dedurre assenza log dal solo encoder.
6. Cron Supabase pg_cron → pg_net → Edge photo-lifecycle autenticata → DB/Storage. Vault contiene credential server, non loggarla. Claim/retry/purge e receipt tecnici PHOTO restano soggetti al lifecycle verificato, non riaperto qui.
7. Operatore → Gmail per richieste supporto/privacy/safety/ricorso; può arrivare UGC sensibile. Non inoltrare a venue/università, GitHub, Figma o strumenti AI. Account delete non cancella automaticamente inbox/ticket.
8. Operatore/CI → GitHub/Actions/npm; CLI → Vercel artifact statico; CLI/dashboard → Supabase codice Edge. Build/deploy possono conservare sorgenti/env/log. Fonte GitHub non deve contenere dump o utenti reali; CI usa URL/key placeholder, nessuna credenziale produzione nel workflow trovato.
9. **Solo staging futuro:** AGE/CONSENT/RETENTION aggiungono prove età/consenso e metadata purge privati a Supabase. Non vanno elencati come dati già nuovi in produzione; limiti7/30 giorni del design non configurano automaticamente provider/Auth logs/backups.
